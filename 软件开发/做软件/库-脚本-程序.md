# 脚本：
是一种纯文本格式的可执行文件或指令集。由计算机语言（Shell,Python,JavaScript,Groovy,Kotlinbat）写成的执行时由系统解释器逐条翻译成机器可识别的指令并按顺序执行
# 解释器：
将代码转换为二进制的语言（在IDE中点击“运行”后，系统用命令行调用指定路径下的python解释器，将当前脚本文件作为参数传入），一边读源代码一边翻译成机器码并执行
# 编译器：
先全部编译成机器码（.exe)或中间码（中间码）(.jar/.class)，编译好后的产物是一个独立的，可执行的文件，比如windows系统c语言中编译好的程序叫.exe而库（lib）则是.dll,Linux和macOS通常没有文件扩展名而靠文件权限来判断能不能跑（可执行位x，这个以后有需求再学）Java编译好后的字节码是.class,库或程序则是.jar，如果最后编译成机器码则点击直接跑，如果是中间码还需要靠环境（比如JVM来解释+编译）成机器码才能跑
## .jar
把.jar的扩展名改成.zip后用任何解压软件都能打开，jar=zip+java convention(惯例，约定，协议)，在zip的基础上让JVM和工具能直接识别，加载和声明入口类，版本信息等
# JDK>JRE>JVM：
- JVM:Java virtual machine,安装在操作系统上的一个程序，为java字节码提供一个运行环境，负责把字节码通过解释执行（逐条翻译成机器码）或JIT编译（把频繁执行的方法或循环编译成本地机器码缓存起来后续直接跑机器码）（**既解释又编译**)翻译成当前平台能执行的机器码，任何能翻译成字节码的语言（java,kotlin,scala,groovy,clojure)都能跑在JVM上
- JRE:Java Run Environment，可以运行别人写好的Java程序，但不能自己写代码编译
- JDK：Java Development Kit（套件，成套工具），Java开发包，JDK=JRE+开发工具
	- javac
	- java
	- javap
	- jar
	- javadoc
	- jdb
	- jps
	- jstat
	- jmap
# 字节码：
由源代码经过javac编译而来，给JMV虚拟机识别的二进制语言，放在.class文件里，
# 机器码：
给cpu识别的二进制语言，不同的cpu架构有不同的编码规则

# 从C语言到程序的流程
C 源码 (.c) ──编译──▶ 机器码(.o/.exe) ──▶ CPU 直接跑
# 从Java语言到程序的流程
Java 源码 (.java)
   │  javac 编译
   ▼
字节码 (.class)          ← 编译产物，不是机器码
   │  jar 打包（底层是 zip）
   ▼
.jar 文件                ← zip 容器 + MANIFEST 约定
   │  靠 JVM 加载运行
   ▼
程序执行

# 构建系统
是一个服务于特定语言的编译规则和特定平台的运行环境
JVM生态：Gradle
C/C++:CMake,Bazel
前端Web开发：Vite,Webpack,Rollup
IOS/macOS:Xcode,SPM(Swift Package Manager)
Rust语言：Cargo
Go语言：Go Modules(go build)
# 软件测试
## 边界值测试（Boundary Value Test）
绝大部分的bug不出现在“正常”的数据中，而是在输入范围的边界附近，如果软件在边界附近运行正常，那么在范围内的正常值大概率也能运行正常。

git：一个开源免费的软件，功能是版本控制，当一个文件夹被git管理起来时，就变成了一个git仓库，被git仓库管理的文件夹下面会生成一个.git的子文件夹用来存放git的版本控制信息，git用commit作为版本控制的基本单元，每完成一次commit，git都保存了一个仓库，此时文件夹里所有文件的状态都被记录了下来，随着commit越来越多，会形成一条commit的历史链路，这样整个仓库都是可回溯的，每个项目参与者的每一次改动都会被这个commit链路记录下来，git的仓库分成两种分别是本地仓库（local repository）和远端仓库（remote repository），GitHub就是一个免费提供远端仓库的网站，hub的意思是中心，汇聚，集合，全世界的很多开发者会把自己用git进行版本控制的仓库，也就是一个个项目的文件夹上传到GitHub网站上
将本地文件和远端仓库联系：发送给ai：把这个文件（初始化成git项目，并）推送到GitHub上面，远端仓库的地址是XXX
init（初始化）：把文件夹用git管理起来，让这个文件夹变成一个git仓库
.gitignore：一个文件，这个文件声明了仓库里哪些文件不应该受到git管理
 - 操作：打开VS code，在仓库根目录上面创建一个.gitignore文件然后在里面写上不被管理的文件
 - 补充：查看是否被管理：
    - 1.在文件资源管理器找到上方复制文件夹的地址
    - 2.在终端（win+R+cmd）用cd命令进入文件夹：cd 粘贴刚才复制的文件
    - 在终端输入git ls-files查看文件中被git管理的文件
- 在终端移出git的管理：git rm --cached 在这个文件夹中需要移出的文件路径（git的同级目录开始）（本地移出）（移出之前要先用cd命令打开）
- git commit -m "移除 *文件路径* 的版本控制"（把更改提交给远端仓库）
commit：每保存一次历史版本就是一次提交，随着commit越来越多，会形成一条commit的历史链路
想看远程有什么更新：在终端运行git pull origin master
origin：是Git给远程仓库默认起的别名，Git会将远程地址命名为origin，而master时远程仓库的分支名称，因此origin/master就是“远程仓库的master分支”
创建新分支：基于你现在当前所在的分支创建一个全新的分支
创建新分支依据：在已有分支的基础上创建新分支
签出（已分离）（checkout（detached））：点击后整个仓库就会回退到某个历史版本，不过这个状态只适合查看代码，不适合更改代码，因为detached表示分离头指针，表示不处于任何一个分支的管理中，在里面修改容易搞丢代码，想退回去的话点左下角，然后选择回你要的分支，而如果你想基于这个历史版本开发，请务必点击列表顶部的创建新分支。
commit ID：把鼠标放到某一次提交上面，有一个数字+英文的小编号就是这个ID，这个ID是git通过哈希算法自动计算出来的，一个ID有长有短，一个commit ID在一个仓库里是绝对唯一的，如果我们需要把仓库回退到某一个历史版本，可以在这个版本上右键，然后复制提交哈希(Copy Commit Hash)，然后把这串长ID粘贴给ai，告诉它把仓库回退到ID提交的状态，后面的改动都不要了（ai在底层执行git，reset —hard），如果需要撤回某次提交而不修改后面的提交，让ai把ID的这次提交撤销掉，保持其它不变（ai 在底层执行的是revert命令），不过其实没必要改得这么决绝，把错的历史保留下来也没什么要是这么决绝的改掉了，而以后又发现其实没问题又要后悔自己的冲动了。
合并分支：可以指挥ai合并
删除分支时要先切换到其它分支，但最好不要删分支，删了以后可能又会后悔自己的冲动了
head：当前分支处于哪次commit上
worktree：建立一个不影响主干文件夹的开发环境
工作区（working directory）：电脑磁盘上的本地文件夹
git clone：把远端仓库保存到本地
git add（添加所有修改到暂存区）+git commit：把本地工作区的改动同步到本地仓库
git push（将本地仓库的改动推送到远端仓库）
git pull=git fetch（将远端仓库同步到本地仓库）+git merge（将本地仓库内容同步进本地工作区）
地址转换规则：
https格式:https://github.com/用户名/仓库名.git
SSH格式：git@github.com:用户名/仓库名.git
sync changes ⬆️：把远端仓库的提交同步到本地仓库
快捷键：/，快速打开搜索功能
T：快速定位到文件搜索栏
L：直接定位文本行号
？：快捷键的快速速查表
。：打开网页版的vs code
fork（叉子，分叉）：复刻，把项目保存一份到自己名下
协作：先fork一个到自己的vs code里，动手修改代码之前一定要创建分支，这样在同步代码时不会产生冲突，而且要确保自己已经包含了母项目那边最新的代码，可以让ai帮忙同步：告诉ai母项目地址，我要你要母项目的最新改动合并进当前分支，如果有冲突让我选择怎么处理。注意是把多的分支合并进少的的分支
